C5. Understanding (written notes)

C5.1 Difference between updateOne and updateMany.
- updateOne updates only the first document that matches the filter.
- updateMany updates every document that matches the filter.
- Example:
  db.tasks.updateOne({ status: "todo" }, { $set: { status: "done" } })
  db.tasks.updateMany({ status: "todo" }, { $set: { status: "done" } })
- updateOne changes one match; updateMany changes all matches.

C5.2 What does an upsert do? Write the option flag.
- An upsert means: if a matching document is not found, insert a new one with the filter and update data.
- The flag is: { upsert: true }
- Example:
  db.tasks.updateOne(
    { title: "New Task" },
    { $set: { status: "todo", points: 1 } },
    { upsert: true }
  )
- If "New Task" already exists, it updates; otherwise it creates it.

C5.3 Difference between $set, $inc, $push, $addToSet in one line each.
- $set: replace a field value.
- $inc: increase a numeric field by a value.
- $push: append an item to an array.
- $addToSet: append an item only if it is not already present in the array.

Generic notes for MongoDB operations

- find({...}) -> read matching documents
- findOne({...}) -> read the first matching document
- updateOne({...}, {...}) -> update only one matching document
- updateMany({...}, {...}) -> update all matching documents
- deleteOne({...}) -> delete one matching document
- deleteMany({...}) -> delete all matching documents
- countDocuments({...}) -> count matching docs
- $set -> change a field’s value
- $inc -> increase a numeric field
- $push -> add to array
- $pull -> remove from array
- $addToSet -> add to array only if unique
- projection: second argument in find/findOne decides which fields come back
  Example: { _id: 0, title: 1, points: 1 }
- filter: first argument decides which documents match
- raw array tags example: tags: ["Go", "http"]
- the `_id` field is auto-generated by MongoDB unless you provide your own

These practical rules make MongoDB shell work easier:
- filter first, then projection second
- use update operators to change fields without rewriting the whole document
- use arrays when a field can hold multiple related values like tags

Q: when its one like findOne, updateOne deleteOne -- which one is picked up ? order by inserted time desc or anything like that?
A:  if you do not specify a unique match condition,
    findOne / updateOne / deleteOne can target different matching docs at different times because the default order is not guaranteed.
